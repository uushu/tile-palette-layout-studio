# Tile Palette Layout Studio

Tile Palette Layout Studio is a small Unity Editor workflow for reviewed Tile Palette layouts.

The layout decision is made by a developer or Codex in a project-specific Recipe. The package validates that Recipe, stores the result in a Profile, previews the final two-dimensional layout, builds the Palette transactionally, and synchronizes manual Palette edits after Ctrl+S.

## Workflow

Loose Sprite assets
→ developer/Codex Recipe
→ Profile
→ final 2D Layout Preview
→ Build Palette
→ independent Validate
→ manual Palette edits and Ctrl+S Profile sync

The package does not contain an active AI provider, API key, model configuration, HTTP transport, proxy logic, or network dependency.

## Requirements

- Unity 2022.3 or newer
- Unity 2D Tilemap
- A source folder containing imported Sprites
- A folder for generated ordinary Tile assets
- A Palette prefab containing a Tilemap
- A reviewed Recipe generated by the developer or Codex

## Installation

In Unity Package Manager choose Add package from git URL and enter:

https://github.com/uushu/tile-palette-layout-studio.git

For local development, choose Add package from disk and select package.json.

## Quick start

1. Open Tools → Tile Palette → Layout Studio.
2. Create or select a Profile.
3. Assign the Source Folder, Tile Output Folder, and Palette Prefab.
4. Apply the project-specific Recipe generated by the developer or Codex.
5. Review the final Layout Preview.
6. Click Build Palette.
7. Run Validate independently after the build.
8. Move or delete Palette Tiles manually, then press Ctrl+S to synchronize the Profile.

## Safety rules

Build validates before writing, writes the Palette and Profile, and validates again. If writing or validation fails, the previous Palette/Profile bytes are restored and Tiles created by that Build are removed.

Unknown external Tiles remain in the Palette and produce warnings. Duplicate known Tiles block synchronization and Build; the Profile file is restored to its pre-sync bytes.

Repeated Build is idempotent: once the Palette matches the Profile, a second Build creates zero Tiles and moves zero Tiles.

## Recipe API

The generic Recipe API lives in TilePaletteLayoutRecipe. A consuming project supplies its own groups, origins, and relative tile coordinates. A Recipe must not assign a Sprite more than once, reuse a target cell, or reference a missing Sprite.

Project-specific Recipes, source folders, Sprite names, generated Tile assets, Palette content, and project quantities stay in the consuming project. They are not part of this package.

## Editor architecture

- TilePaletteLayoutRecipe: developer/Codex Recipe construction and validation
- TilePaletteProfile: serialized source, Palette, groups, and final positions
- TilePaletteLayoutStudioWindow: Build Palette, Validate, and the final Layout Preview
- TilePaletteBuilder: planning, transactional Build, validation, and rollback
- TilePaletteAutoSync: Ctrl+S synchronization for manual Palette edits
- TilePaletteProfileUtility: final positions, bounds, and managed-cell helpers

## Tests

The package includes EditMode tests for Recipe input validation, Profile layout bounds, and managed-cell holes. The consuming project also has a full local validation entry point covering Recipe coverage, Build idempotence, Build rollback, Ctrl+S movement/deletion, duplicate conflicts, unknown Tile warnings and preservation, and temporary asset cleanup.
